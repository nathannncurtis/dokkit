Your AI agents can watch it too.

Everything the interface shows comes from one API. A script, the command line and an AI tool all reach it the same way, each with a token that says how far it may go.

A token for an agentdku_… · made in Settings
Read states, issues, jobs and errorson
Read what is written in the logs
Snooze, mark as seen, watch, run tasks you accepted
Everything you can do: keys, people, rules, checks
A token that can do everything

Whatever holds it can make and revoke keys, add and remove people, and change who is told, with nobody asked first. Dokkit makes you type its own address and tick a box.

Sample answers on the sample data. The tools are the real ones, with ids and times shortened here, and they follow the token on the left.

  1. An AI tool, over MCP
    claude mcp add --transport http dokkit https://your.domain.com/mcp --header "Authorization: Bearer dku_..."
  2. A script, over the API
    curl -H "Authorization: Bearer dku_..." https://your.domain.com/api/v1/inbox
  3. In an app's repo, from the command line
    dokkit check
    Runs every check once and prints what would be sent. No server needed.
  4. All of it, in one file an agent can read
    https://dokkit.dev/llms-full.txt
    The API, every command, the MCP tools and the dokkit.toml reference. Paste the link and it knows how.

An agent can be given everything you can do, and Dokkit asks you to be sure before it makes that token. The whole API and every command are written down.

You build it. You are also the only one watching it.

dokkit.toml
schema = 1

[service]
id = "upload-portal"
name = "Upload portal"

[[check]]
type = "http"
url = "http://localhost:8080/healthz"
every = "30s"
slow = "2s"                # slower is degraded, not down

[[job]]
id = "nightly-purge"
schedule = "0 1 * * *"   # every night at 01:00
grace = "30m"

[logs]
path = "logs/*.jsonl"
Wired in while you build
dokkit init writes the file and dokkit check proves it on your own machine, with no server. Run the app as dev and it shows up without ever alerting.
A deploy is noticed by itself
When the version an app reports changes, that is a deploy. What broke since the last one is a single question, for you or for your agent.
The app describes itself
A dokkit.toml in the app's own repo says what it is and how to tell it is healthy. Nothing is wired in by hand on the server.
Nothing privileged listens
The program on each machine opens no port. Work reaches it over a connection it makes itself, and only tasks you accepted can run.
Scanning is offered, never required
Let it look over a machine and propose what to watch, or list things yourself. Nobody is asked to turn off antivirus.
On your hardware
A Windows service or a Docker container, on Postgres. Logs stay a year live, then go to an archive folder you name.
One list, not six tools
Checks and scheduled jobs feed one short list. Logs, errors, versions and deploys sit one click from each item on it. An issue closes by itself when the thing recovers.
In eleven languages
A small library adds what only the app knows: beat, job, check, capture and log, with a handler for the language's own logging where it has one. Python, .NET, JavaScript, Go, Rust, Java, PHP, Elixir, Swift, PowerShell and shell.

Yours to run.

One server. Then one small program on each machine you want watched.

The server, one of these

  1. A fresh Debian or Ubuntu VPS, with a domain pointed at it
    curl -fsSL https://dokkit.dev/install.sh | sudo sh -s -- your.domain.com
  2. The same, from a checkout of the source
    sudo sh server/install.sh your.domain.com
  3. Windows, as a service, from an administrator PowerShell
    irm https://dokkit.dev/install.ps1 | iex

Then

  1. On each machine you want watched, get the program
    curl -fsSL https://dokkit.dev/get.sh | sh
    irm https://dokkit.dev/get.ps1 | iex
  2. Join it to your server
    dokkit enrol https://your.domain.com <token>
  3. Keep it running with nobody signed in: an administrator prompt on Windows, sudo on Linux
    dokkit service install
  4. In each app's own folder, describe it, then say where it lives
    dokkit init
    dokkit folder add .

What the server needs

Estimates for about ten machines and sixty services. They have not been measured yet. The program on each watched machine needs next to nothing.
