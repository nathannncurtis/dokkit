What it watches, and when it says so.

ThingHow it is watchedIt needs you when
Websites and APIsAn address is asked on the schedule its file sets, from the machine it runs on.Three answers in a row are wrong, or slower than the limit its file sets.
Scheduled jobsThe job reports a start and an end, or is wrapped with dokkit run.It does not start on time, fails, or runs longer than you allow.
Services and processesWindows services, systemd units, ports and named processes.One stops, or fewer are running than the count you set.
Disks, memory, certificatesRead on every machine with the dokkit program.A disk is on course to fill, or a certificate expires within 30 days.
LogsFiles it is pointed at, apps that log to Seq, and the libraries. Kept a year, then archived.Never by itself. Logs are for looking things up, one click from each item.
ErrorsFrom the library, or from Sentry's own SDKs, grouped by type and place.Never by itself. What is new since the last deploy is one click away.
Versions and deploysThe version each app reports. When it changes, that is a deploy.Never by itself. What broke since the last deploy is one question.

A machine that goes down is one page, not one for every service on it. An issue closes itself when the thing recovers.

If you build it

An app describes itself in a dokkit.toml in its own repo. Hand an agent one link and it can do the wiring: write the file, add the library in your language, and prove it with dokkit check, before any server exists.

If you watch it

You decide who hears about what, per service: a page for the job that must run, a push for the slow portal, the morning digest for the rest. On a phone, a read-only app shows it all through a relay the server dials out to.

  • Where alerts can reach you
  • The phone app
  • Our own status, by Dokkit

If you have to trust it

The program on each machine opens no port. Work reaches it over a connection it makes itself, and only tasks you accepted can run. Releases are signed, and you can check one yourself. It runs on Postgres on your own hardware.
