Dokkit/Get started/Install

Install

One server, then a small program on each machine you want watched. Four steps, in order. The step you are on is always marked.

  1. 1The server
  2. 2The first visit
  3. 3Each machine
  4. 4Each app

What the installer does 3 things
  • Installs Docker and its compose plugin if they are missing, and writes its settings to /opt/dokkit/.env.
  • Starts three containers: Postgres 17, the Dokkit server, and Caddy, which gets and renews the certificate for by itself.
  • Waits until the server answers over https, then prints the address and a setup code for the first visit.

Its database is , at .

Run it from an administrator PowerShell.

What the installer does 3 things
  • Fetches the release and refuses it unless its checksums carry a valid signature from the release key.
  • The first time, sets up Postgres 17 as a Windows service of its own that listens on this machine only.
  • Installs Dokkit as a Windows service and starts it. Without a certificate it serves plain http to this machine only; give it one with -Cert and -CertKey, or get one later in Settings.

Step 2 of 4

The first visit

  1. Open in a browser.
  2. Type the setup code the server printed when it started. It is there so nobody else on the network can claim the server first.
  3. Make the owner account. That is you.

Dokkit cannot page you about itself when it is down. In Settings, give it an outside heartbeat: an https address it calls every minute, at any service that alerts when the calls stop. Soon dokkit.dev itself will take that heartbeat, so there is nothing else to sign up for.

Step 4 of 4

Each app

  1. In the app's own folder, describe it. This asks what the app is and writes dokkit.toml:
    dokkit init
  2. Prove it on your own machine. It runs every check once and prints what would be sent, with no server needed:
    dokkit check
  3. On the machine where it runs, tell the program where it lives:
    dokkit folder add .
