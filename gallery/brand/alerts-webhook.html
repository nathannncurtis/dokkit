Dokkit/Alerts/Webhook

Webhook

A JSON request to an https address of yours when an issue opens, and another when it closes. Use it to reach anything Dokkit does not speak to directly.

  1. 1Set it up
  2. 2What it sends
  3. 3Try it

Set it up

On Dokkit's Alerts page, in Settings. Only the owner can change it.

Webhook addressOn Dokkit's Alerts page, under Webhook, an address that starts with https://.
Who is toldTick Webhook for the states it should hear about, alone or beside another channel.

What it sends

The request it sends:

{
  "event": "opened",
  "issue": {
    "id": "DOK-12",
    "title": "nightly-purge did not run",
    "note": "It was due at 01:00 and no start was reported.",
    "machine": "db-01",
    "state": "down",
    "url": "https://dokkit.example.com"
  }
}

When the issue closes, the same request comes again with "event": "closed".

Try it

Under Webhook, press Send a test. It says at once whether it went, or why not.

  • A Slack or Discord webhook address gets a message in their own format instead.
  • Addresses on your private network are allowed. Addresses that point at the server itself, or link-local ones, are refused unless the server runs with DOKKIT_ALLOW_LOCAL_ALERTS=1.
